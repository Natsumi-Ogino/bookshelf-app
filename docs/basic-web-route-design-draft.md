# BookShelf Basic版 Web機能・ルート設計案

## この文書の位置付け

この文書は、要件シートのシート5「画面設計」、シート6「デザインUI」、シート7「機能要件」、提供されたBasic版Blade、2026年9月8日、9月15日、9月16日および9月17日のコーチ回答を照合した設計案です。

画面遷移、成功メッセージ、自分のレビューへのいいね禁止、レビューコメント、バリデーションエラーメッセージ、テスト範囲、Basic版公開APIの仕様は確認済みです。

## アクセス制御

| 区分 | 対象機能 |
|---|---|
| ゲスト閲覧可 | 書籍一覧、書籍詳細、ランキング |
| ログイン必須 | 書籍登録、お気に入り一覧・切り替え、レビュー投稿・いいね、ジャンル管理 |
| ログインかつ所有者本人 | 書籍の編集・更新・削除、レビューの編集・更新・削除 |
| Fortifyが担当 | 会員登録、ログイン、ログアウト |

存在しない書籍、レビュー、ジャンルは404とし、「お探しのページが見つかりません。」と表示します。書籍またはレビューに対して所有者以外が編集・更新・削除を試みた場合は、Policyによって403とし、「この操作を行う権限がありません。」と表示します。どちらのエラー画面にも書籍一覧画面（`/`）へ戻るリンクを設けます。

## ルート設計

### ゲストも利用できるルート

| HTTP | URI案 | ルート名 | Controller | 用途 |
|---|---|---|---|---|
| GET | `/` | `books.index` | `BookController@index` | 書籍一覧 |
| GET | `/books/{book}` | `books.show` | `BookController@show` | 書籍詳細 |
| GET | `/ranking` | `ranking.index` | `RankingController@index` | 評価ランキングTOP10 |

## ControllerとBladeの対応

### BookController

| メソッド | Blade | 渡すデータ | 主な取得条件 |
|---|---|---|---|
| `index` | `books.index` | `$books` | ジャンルと平均評価を取得し、10件ずつページネーション |
| `show` | `books.show` | `$book` | ジャンル、レビュー投稿者、レビューへのいいねをまとめて取得 |
| `create` | `books.create` | `$genres` | 全ジャンルを取得 |
| `store` | なし | なし | 書籍を登録し、選択されたジャンルを紐付け |
| `edit` | `books.edit` | `$book`, `$genres` | Policyで所有者認可し、全ジャンルを取得 |
| `update` | なし | なし | Policyで所有者認可し、書籍とジャンル紐付けを更新 |
| `destroy` | なし | なし | Policyで所有者認可し、書籍を削除 |

`index`と`show`ではEager Loadingと集計機能を使い、N+1問題を防止します。

### ReviewController

| メソッド | Blade | 渡すデータ | 主な処理 |
|---|---|---|---|
| `store` | なし | なし | ログインユーザーのレビューを対象書籍へ投稿 |
| `edit` | `reviews.edit` | `$review` | Policyで投稿者認可して編集画面を表示 |
| `update` | なし | なし | Policyで投稿者認可して更新 |
| `destroy` | なし | なし | Policyで投稿者認可して削除 |

レビュー登録時はDBの複合ユニーク制約に加え、入力処理でも同一ユーザー・同一書籍への重複投稿を防止します。

### FavoriteController

| メソッド | Blade | 渡すデータ | 主な処理 |
|---|---|---|---|
| `index` | `favorites.index` | `$books` | ログインユーザーのお気に入り書籍を10件ずつ表示 |
| `toggle` | なし | なし | 対象書籍のお気に入りを追加または解除 |

一覧取得時は書籍のジャンルをEager Loadingします。

### ReviewLikeController

| メソッド | Blade | 渡すデータ | 主な処理 |
|---|---|---|---|
| `toggle` | なし | なし | 対象レビューへのいいねを追加または解除 |

自分が投稿したレビューにはいいねできないようにします。

### GenreController

| メソッド | Blade | 渡すデータ | 主な処理 |
|---|---|---|---|
| `index` | `genres.index` | `$genres` | 各ジャンルに紐付く書籍数を集計して表示 |
| `show` | `genres.show` | `$genre`, `$books` | 対象ジャンルの書籍をジャンル情報付きで10件ずつ表示 |
| `create` | `genres.create` | なし | 登録画面を表示 |
| `store` | なし | なし | ジャンルを登録 |
| `edit` | `genres.edit` | `$genre` | 編集画面を表示 |
| `update` | なし | なし | ジャンルを更新 |
| `destroy` | なし | なし | 書籍が紐付いていない場合だけ削除 |

ジャンル管理はログインユーザー全員が利用でき、所有者による区別はありません。

### RankingController

| メソッド | Blade | 渡すデータ | 主な処理 |
|---|---|---|---|
| `index` | `ranking.index` | `$rankedBooks` | レビューがある書籍だけを平均評価の降順、レビュー件数の降順、書籍IDの昇順で最大10冊取得 |

平均評価が同じ場合はレビュー件数の多い順、さらに同じ場合は書籍IDの昇順で並べます。

| レビュー削除 | なし | `ReviewPolicy@delete` |

## バリデーションルール

### 書籍

| 項目 | ルール |
|---|---|
| title | 必須、文字列、最大255文字 |
| author | 必須、文字列、最大255文字 |
| isbn | 必須、半角数字13桁、重複不可。更新時は更新対象自身を一意性確認から除外。チェックディジット検証は行わない |
| published_date | 必須、有効な日付。未来日も登録可能 |
| description | 任意、文字列 |
| image_url | 任意、URL形式、最大2048文字 |
| genres | 必須、配列、1件以上 |
| genres.* | 整数、重複不可、`genres.id`に存在 |

### レビュー・ジャンル・認証

| 項目 | ルール |
|---|---|
| rating | 必須、整数、1から5 |
| comment | 必須、文字列、最大1000文字 |
| ジャンル名 | 必須、文字列、最大255文字、重複不可。更新時は更新対象自身を一意性確認から除外 |
| 会員登録の名前 | 必須、文字列、最大255文字 |
| 会員登録のメールアドレス | 必須、メール形式、最大255文字、重複不可 |
| 会員登録のパスワード | 必須、8文字以上、確認入力と一致 |
| ログインのメールアドレス | 必須、メール形式 |
| ログインのパスワード | 必須 |

## Basic版公開API設計

### エンドポイントと認証

| HTTP | URI | 処理 | Basic版の認証 |
|---|---|---|---|
| GET | `/api/v1/books` | 書籍一覧 | 不要 |
| GET | `/api/v1/books/{book}` | 書籍詳細 | 不要 |
| POST | `/api/v1/books` | 書籍登録 | 不要 |
| PUT | `/api/v1/books/{book}` | 書籍更新 | 不要 |
| DELETE | `/api/v1/books/{book}` | 書籍削除 | 不要 |

### 一覧取得

- `keyword`は任意の文字列、最大255文字とし、`title`または`author`への部分一致検索に使用する。
- `genre`は`genres.id`に存在するジャンルIDとする。
- `keyword`と`genre`を同時に指定した場合は、両方の条件を満たす書籍を取得する。
- 登録日時の新しい順で表示する。
- 1ページ当たりの初期件数は20件とし、`per_page`で1件から100件まで指定可能とする。
- `page`は1以上の整数とする。
- レスポンスは`data`、`links`、`meta`を含むページネーション形式とする。

### API Resource

`BookResource`に含める項目は次のとおりです。

- `id`
- `title`
- `author`
- `isbn`
- `published_date`
- `description`
- `image_url`
- `genres`
- `average_rating`
- `review_count`

登録者情報、`created_at`、`updated_at`は含めません。平均評価は小数第1位までの数値とし、レビューがない場合は`null`を返します。

書籍詳細に含める`ReviewResource`の項目は次のとおりです。

- `id`
- `user_name`
- `rating`
- `comment`
- `created_at`

投稿者IDと`updated_at`は含めません。`created_at`はタイムゾーンを含むISO 8601形式で返します。詳細・登録・更新APIは、`data`に書籍情報を含めます。

### 登録・更新

- 登録APIは`user_id`、`title`、`author`、`isbn`、`published_date`、`description`、`image_url`、`genres`を受け取る。
- `genres`にはジャンルIDの配列を指定する。
- `user_id`は必須の整数とし、`users.id`に存在することを検証する。
- Basic版の更新APIでも、`user_id`は存在確認だけを行う。
- Basic版では、更新時に現在の登録者との一致確認を行わず、`user_id`を更新対象から除外しない。
- 所有者認可はAdvanced版でSanctum認証と`BookPolicy`を導入した際に行う。
- `published_date`は`YYYY-MM-DD`形式で返す。

### HTTPステータスコードとエラーレスポンス

成功時のHTTPステータスコードは次のとおりです。

| 処理 | HTTPステータスコード | レスポンス本文 |
|---|---|---|
| 書籍一覧取得 | 200 OK | あり |
| 書籍詳細取得 | 200 OK | あり |
| 書籍登録 | 201 Created | あり |
| 書籍更新 | 200 OK | あり |
| 書籍削除 | 204 No Content | なし |

バリデーションエラーはHTTP 422 Unprocessable Entityとし、`message`と`errors`を返します。

```json
{
  "message": "<エラー概要>",
  "errors": {
    "項目名": [
      "エラーメッセージ"
    ]
  }
}
```

`message`にはエラーの概要を、`errors`には項目ごとの日本語バリデーションメッセージを設定します。

対象の書籍が存在しない場合はHTTP 404 Not Foundとし、`error`のみを返します。

```json
{
  "error": "書籍が見つかりませんでした。"
}
```

## Basic版テスト設計

次の検証範囲はコーチ確認済みです。

- モデル、画面アクセス、認証、書籍CRUD、レビュー、ジャンル、お気に入り、レビューへのいいね、ランキング、公開APIの正常系と異常系。
- 未ログイン時のログイン画面へのリダイレクト。
- 書籍・レビューの所有者本人による操作成功と、他人による操作の403 Forbidden。
- 画面表示、登録、更新、削除、バリデーションエラー、遷移先、フラッシュメッセージ、DB状態、関連データ削除。
- お気に入りとレビューへのいいねの追加、解除、再追加、重複防止、未ログイン制限。
- ランキングの平均評価順、TOP10制限、レビューなし書籍の除外、同率時の並び順。
- 公開APIの各エンドポイント、検索、ジャンル絞り込み、ページネーション、JSON構造、ステータスコード、DB状態、秘密情報の除外。
- 開発用DBとテスト用DBを分離し、DBを使用するFeatureテストでは`RefreshDatabase`を使用する。
- バックエンド処理はPHPUnitのFeatureテストで検証し、画面の見た目とJavaScriptは手動確認する。Laravel Duskは導入しない。
- レビューの投稿・編集・削除、評価範囲、コメント条件、重複投稿、所有者認可、自分のレビューへのいいね禁止。
- ジャンルの登録・編集・削除、名前重複、書籍紐付きジャンルの削除拒否、ログイン必須制御。

## Basic版完成時の確認
